# Fuzz harness for the style value parsers and the tree builders

Targets (`dotnet OneRender.Fuzz.Values.dll --list` is not needed; run without arguments for usage):

- `values`: first byte picks a property (odd bytes: the text is UTF-16), the rest is a value declared on a parent and a child, computed through the builder front end, then a box tree is built.
- `tree`: bytes are operations that grow a random styled tree with small limits; a second build into the retained arenas must give the same box dump.
- `html`: bytes are an HTML document (a form feed starts an author style sheet); the HTML front end and box tree run on it.
- `layout`: as `html`, then block layout (floats, clearance, boxes beside floats) at a width taken from the first byte; laying out again into the retained fragment tree and into a fresh one must give the same fragments.
- `inline`: as `layout`, with the real default fonts: inline layout at a width from the first byte. A second layout into the retained tree and a fresh one must agree, geometry must be finite, text ranges inside their text, and min-content no wider than max-content.

A target must never throw. Modes: `<target> <file>` replays one input; `<target> --mutate <seconds> <seed-dir>` is a coverage-blind mutation loop; `<target>` alone is the libFuzzer target under SharpFuzz. `run.sh <target> <seconds> <seed-dir> <out-dir>` publishes, instruments `OneRender.dll` and runs the libFuzzer driver (the prebuilt `libfuzzer-dotnet`, pinned by tag and SHA-256 in `setup.sh`), user-local, no sudo. Seeds are in `seeds/<target>/`.
- `flex`: bytes are pairs of operations that grow a random tree of flex, inline-flex and block boxes and set flex-related and sizing properties from small vocabularies; flex layout runs at a width from the first byte. Laying out again into the retained fragment tree and into a fresh one must give the same fragments, every border box must be finite and not negative, and every fragment of the tree must be reachable from its root.
- `fragmentation`: bytes pick a multi-column container (count, width, height, fill) and then grow a random tree of blocks, text and floats with break, column, sizing and decoration properties from small vocabularies. The same tree is laid out with and without the column and break properties; every box must keep all its lines and fragments (nothing lost or duplicated), the fragments of a box must follow the columns in order, laying out again into the retained and into a fresh fragment tree must agree, border boxes must be finite and not negative, and every fragment must be reachable from the root exactly once.
